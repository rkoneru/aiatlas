# Review: code, performance, accessibility, security (24 Nov 2026)

This is a review of the site as built from this repository after the v23 content and the phone app layout. It covers performance (the reported slowness), code, accessibility, security and dependencies.

**How it was measured:**
- Headless Chromium with a 4× CPU slowdown, to approximate a mid-range phone.
- Lighthouse 13 (mobile emulation).
- axe-core at 390 px wide, light and dark.
- The full test suite.

## Performance

### What was slow

| Where | Measured (4× CPU) | Cause |
|---|---|---|
| Typing in the glossary search | Up to 264 ms per key | Each key redrew all 308 terms. The phone layout then rebuilt 308 tiles, and the accessibility enhancer rescanned the whole page. |
| Any change on the page (diagram step, slider, tile tap) | 70–100 ms | The accessibility enhancer re-ran over **every** element after every change, calling `getComputedStyle` on each, thousands of diagram shapes included. |
| Loading `/proposal/`, `/acumen/`, `/` | Long tasks of 0.5–1 s | The same full scan on load, plus `input.labels` for every form field (slow) and layout of 300+ off-screen cards. |
| Navigating between pages on a phone | Page tabs jumped after load (CLS 0.07) | The section tab bar was built from headings the runtime had added and then rebuilt with fewer tabs. |

### What changed

- **Accessibility enhancer** (`src/scripts/a11y.ts`):
  - One full pass on load. After that, only what changed is checked: added elements, and up to four ancestors whose scroll size may have changed.
  - SVG internals and inline elements are skipped.
  - Label checks use `label[for]` and wrapping labels instead of `input.labels`.
- **Search typing:** the glossary and AI Acumen searches redraw 120 ms after typing pauses. These are declared runtime patches `search-debounce-*`, listed in `docs/runtime-adaptations.md`.
- **Long lists:** glossary terms, AI Acumen cards, release-log entries and catalogue cards use `content-visibility: auto`, so cards off-screen aren't laid out or painted until you scroll near them.
- **Phone layout:**
  - The list watcher only watches containers that hold cards or start empty, not calculators.
  - The tab highlighter runs at most once per frame.
  - The tab bar is built from the page's own headings, so it no longer changes after load.

### What's left, and why

- **Hosting cache:** GitHub Pages caches every file for only 10 minutes. Each page also has its own script (about 90 KB gzipped), so moving between pages downloads a new one. Cloudflare Pages, which `docs/deploy.md` already covers, can serve the hashed files with a one-year cache. That would make repeat visits and page-to-page navigation noticeably faster on a phone.
- **AI Acumen** (performance 85) renders 308 interactive rating cards. Making it faster needs a different design for those cards, for example rendering them as you scroll.
- **The glossary's A–Z links** use `href="javascript:void 0"` in the original runtime, which costs SEO 92 on that page. Changing them needs a runtime patch that also handles the hash router; not done.

## Code review

| Finding | Severity | Status |
|---|---|---|
| Regular expressions in the phone layout's inline script lost their backslashes inside a template literal, so tag colours and runtime-list titles failed silently. | Bug | Fixed earlier (`ebbc2ef`). `tests/unit/collapse-inline.test.ts` now checks the emitted script. |
| A comment in the inline script contained the snapshot template's tag. The build searches the page for that tag, so diagram heights weren't reserved and phones saw a large layout shift. | Bug (caught during this review) | Fixed. A unit test makes sure the script never contains the tag. |
| The phone layout's section tabs disagreed before and after the runtime restore. | Bug (CLS) | Fixed. Tabs come from the page's own headings, marked `data-mtab`. |
| The `MutationObserver` for runtime lists was attached to every container with an id, calculators included. | Performance | Fixed. |
| `scripts/snapshot.mjs` failed the build when `/playground/` settled late under load. Seen twice. | Flaky build | Fixed. The final-state check retries up to three times before failing. |
| `define:vars` in `RedirectPage.astro` and `404.astro`. Astro's advisory says it doesn't fully escape `</script>`. | Hardening | Replaced with JSON that has `<` escaped. Only build-time data went in, so there was no live exposure. |
| The `mobile.ts` diagram type was named `Node`, shadowing DOM `Node`. | Typecheck | Fixed earlier (`bdaf989`). |
| Tablet widths (641–860 px): `main` was a scroll container, so the sticky course bar didn't stick. | UI bug (pre-existing) | Fixed: `overflow-x: clip` up to 860 px. |
| HTML injection: places that write HTML (tiles, sheet, tab bar, diagram text versions). | Checked | Every dynamic value is escaped. Icons and colours come from fixed lists. The sheet clones existing DOM. |
| Old trial code: the `.tc`/`.tt` handlers and styles. | Clean-up | Removed with the move to tiles. |

## Accessibility

axe-core (WCAG 2.0, 2.1 and 2.2, A and AA) on all 103 pages at 390 px, light and dark: one violation found and fixed. The ✕ remove buttons on `/vendors/` were 20×18 px, under the 24 px target size at narrow widths without touch; they're now 24 px at every width. The phone sheet was also checked open and closed: no violations.

## Security

- **AI proxy** (`functions/_lib/claude-proxy.ts`):
  - Input is validated: roles, message count, size, image type and size, and the `max_tokens` cap.
  - Logs never contain prompts, replies or IPs.
  - Two fixes:
    - **Rate-limit key:** it no longer trusts `X-Forwarded-For` / `X-Real-IP` unless `TRUST_FORWARDED=on` (unit test added).
    - **Origin check:** documented as browser-only; scripts can set any `Origin`.
- **Turnstile** loads only on the first AI request, and only when its site key is set.
- **No secrets in the repository.** `.env.example` holds placeholders only.

## Dependencies

`npm audit`: **35 → 6** findings after upgrading the local Lighthouse tool (12 → 13).

The 6 that remain are all build-time only; none ship to visitors:
- `astro` (critical), with `sharp`, `zod`, `zod-to-ts` and `esbuild` pulled in by it. These need the Astro 7 major upgrade. The critical advisory concerns `define:vars` (no longer used here) and server islands (not used).
- `satori` (moderate): share-image generation, needs a major upgrade.

**Recommendation:** upgrade to Astro 7 and satori 0.63 as a separate change, with the full parity suite, since it touches the build.
