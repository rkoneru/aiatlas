Advanced prompting & context engineering

Prompt engineering is about wording. Context engineering is about everything the model sees: instructions, examples, tools, memory, retrieved documents and history, assembled fresh for every call within a token budget. Walk the context assembly, then build a budget.

Techniques

Zero-shot & few-shot

Show, don't just tell

Zero-shot: instructions only, which is enough for most tasks with strong models. Few-shot: add 2–5 worked examples when format or judgment is subtle. Pick examples that are diverse and cover edge cases, put them in a consistent structure, and watch for the model copying surface features of the examples.

Self-consistency

Ask several times, take the majority

Sample n independent reasoning paths at non-zero temperature and vote on the final answer. It improves accuracy on math and logic when individual answers are better than chance and errors are independent, at n× the cost. Use it selectively, for example only when the first answer has low confidence.

Prompt templates & variables

Prompts as code

Keep prompts in versioned template files with named slots ({{user_question}}, {{retrieved_docs}}). Escape or delimit user content, keep a stable prefix (system prompt, tool definitions) at the top for caching, and put variable content last. Test templates against an eval set on every change.

Context engineering

Curate the window, every call

Write (save notes and state outside the window), select (retrieve only what this step needs, just in time), compress (summarize or compact long history), isolate (give subagents their own clean context). Order matters: instructions first, stable before variable, the most relevant material near the question.

Meta-prompting

Models writing prompts

Ask a strong model to draft, critique or improve a prompt for a given task and failure cases. Useful for first drafts and for generating test cases, but always verify on real evals.

Prompt optimization

Search, scored by evals

Frameworks such as DSPy treat prompts as parameters: define the task, the metric and examples, and an optimizer searches instructions and few-shot demos that maximize the score. Works best with a solid golden set and a reliable metric.

Context failure modes

FailureSymptomFix
Context poisoningAn early hallucination keeps getting repeatedValidate before writing to memory; start fresh threads
Context distractionThe model fixates on long history instead of the taskSummarize or compact; trim old turns
Context confusionIrrelevant tools or documents lead to wrong choicesLoad only the tools and documents this step needs
Context clashContradictory instructions or facts in the windowOne source of truth; dedupe; date-stamp facts
Lost in the middleFacts buried mid-context get ignoredPut key facts near the start or right before the question
