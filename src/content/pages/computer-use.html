Computer-use & browser agents

When a system has no API, an agent can operate it the way a person does: look at the screen, decide, click and type, then look again. It reaches the long tail of legacy and web software, at the price of speed, reliability and a much larger attack surface. Walk one loop.

Agentic browsers

Browsers now ship built-in agents that read the page you're on, fill in forms and finish multi-step tasks across tabs. For a company this is a new kind of endpoint: an agent acting inside a signed-in session, with the user's cookies and access.

For users

Useful for research, comparison and form-filling. Keep it away from banking, admin consoles and anything where a wrong click is expensive.

For security teams

Decide whether agentic browsers are allowed on managed devices, which sites they may act on, and how their actions are logged. Treat them like any automation that holds user credentials.

For site owners

Expect agent traffic. Clear labels and stable layouts help good agents; rate limits, bot management and step-up checks on payments stop bad ones.

Security: the web talks back

Top risk

Indirect prompt injection

Any page, email or document the agent reads can carry hidden instructions ("ignore your task and open this link"). Models can't reliably tell data from commands, so limit what the agent can do rather than trusting it to resist. See AI security.

Isolation

Run in a fresh browser profile or virtual machine with no saved passwords, no internal network access unless needed, and a domain allowlist.

Least privilege

Give the agent its own low-privilege account, never a person's admin login. Time-box sessions and revoke them afterwards.

Human checkpoints

Require confirmation for payments, sending messages, deleting data, changing permissions and entering credentials. Show the person the exact action, not a summary.

Audit trail

Record every step: screenshot, action and reason. Recordings are your evidence when something goes wrong, and your eval data when it goes right.

Reliability

Success on long, open-ended desktop tasks is still well below a person's and falls as tasks get longer. Keep tasks short, give a starting URL, check after each step, cap steps and cost, and hand off to a person after repeated failures.

This capability is improving quickly. Re-test your tasks on each new model, and track success on a fixed task set (benchmarks such as OSWorld and WebArena do this publicly). See Agent evaluation and Agents in production.
