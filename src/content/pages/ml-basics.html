ML fundamentals

Every LLM, recommender and fraud model rests on the same ideas: learn from data, hold some data back to check yourself, and balance fitting the training data against generalizing to new data. Walk the workflow, then drag the complexity slider to watch overfitting happen.

Three ways to learn

Supervised

Learn from labeled examples

Every input comes with the right answer. Predict a category (classification: spam, churn, defect) or a number (regression: price, demand).

Unsupervised

Find structure without labels

Clustering groups similar items, dimensionality reduction compresses them, and anomaly detection flags the odd ones out. Often run over embeddings.

Self-supervised

Make labels from the data itself

Hide part of the input and predict it: the next token, a masked word, a cropped image patch. This is how LLMs and embedding models pre-train on trillions of unlabeled tokens.

Core ideas

Train / validation / test split

Train on one part, tune choices (model type, hyperparameters, prompts) on a second, and report on a third you touch only once. A typical split is 70/15/15. With time-ordered data, split by time so you never train on the future. The same discipline applies to LLM evals: a golden set you keep tuning against stops measuring generalization.

Overfitting & generalization

A model that memorizes noise scores well on training data and badly on anything new. Signs: training error keeps falling while validation error rises. Fixes: more data, simpler models, regularization, early stopping, data augmentation, cross-validation.

Bias–variance trade-off

Bias is error from assumptions too simple to capture the pattern (underfitting). Variance is error from sensitivity to the particular training sample (overfitting). Total error = bias² + variance + irreducible noise. The sweet spot sits where validation error bottoms out.

Regularization & dropout

L2 (weight decay) penalizes large weights; L1 pushes weights to exactly zero. Dropout randomly switches off units during training so the network can't rely on any one path. Early stopping halts training when validation loss stops improving.

Feature engineering

Turning raw data into informative inputs: ratios, time since last event, rolling averages, one-hot categories, text embeddings. Deep learning learns many features itself, but for tabular business data (the bulk of enterprise ML) good features plus gradient boosting is still hard to beat.

Clustering in practice

Embed support tickets, then cluster them to discover intents. Segment customers by behavior. Group near-duplicate documents before indexing. k-means needs k up front; HDBSCAN finds the number of clusters and labels outliers as noise.
