AI system design: six layers

A production AI system is ordinary system design with a model inside it. Six layers, each resting on the one below: scale and speed, data and retrieval, reliability, AI and agents, security and governance, and observability and evaluation. Learn them in order. Walk the six layers and what each one buys you.

The six layers

Layer 1

Scale & speed

Outcome: stays fast as users grow.

Load balancing spreads requests across servers. Caching keeps answers close to the user; with LLMs add prompt caching and caching of repeated answers. Auto-scaling adds capacity with demand. Rate limiting protects the system; for LLMs, limit tokens per minute as well as requests.

Layer 2

Data & retrieval

Outcome: stores and finds data fast.

SQL or NoSQL depends on how the data is shaped and queried. Sharding splits large data across machines. Vector databases find text by meaning. Hybrid search combines keyword and vector search, and usually beats either alone. See Vector search.

Layer 3

Reliable systems

Outcome: survives failures and spikes.

Replication keeps copies of data. Queues absorb bursts and run long jobs, including agent tasks, in the background. Retry with backoff handles brief failures; make tool calls that write data idempotent so a retry doesn't do the work twice. Failover switches to a standby, including a second model provider.

Layer 4

AI & agents

Outcome: AI that looks things up, acts, and works.

RAG grounds answers in your documents. MCP and tools let the model act on other systems. Agent memory carries facts and progress across turns and sessions. Model routing sends each request to the cheapest model that can handle it. See RAG, MCP and AI agents.

Layer 5

Security & governance

Outcome: data stays safe and the AI can be audited.

OAuth and JWT say who a user, or an agent acting for one, is and what it may do. Zero trust checks every call, including agent-to-tool calls. Guardrails filter what goes into and comes out of the model. Audit logs record every decision and action. See AI guardrails and Human-in-the-loop controls.

Layer 6

Observe & evaluate

Outcome: quality, cost and speed are measured.

Tracing follows one request through retrieval, model calls and tools. SLOs set targets such as time to first token and error rate. LLM evals score answer quality on a fixed test set. Token cost is tracked per feature and per user. See ADLC & LLMOps and Eval Hub.

What changes when there's a model inside

Building blockClassic systemWith LLMs and agents
CachingSame request, same responsePrompt caching for long, repeated context; caching similar questions needs a quality check
Rate limitingRequests per secondTokens per minute, per user and per model, plus a spend cap
QueuesJobs take secondsAgent tasks can take minutes or hours; persist their state so they can resume
RetriesSafe for readsA retried tool call can send an email twice: use idempotency keys on writes
FailoverA standby serverA fallback model, with prompts and evals tested against it beforehand
Access controlUsers and servicesAgents get their own identity and the narrowest permissions for each task
TestingSame input, same outputOutputs vary: score them on a test set and watch the scores over time
CostMostly fixed infrastructureGrows with every token: budget per request and per feature
