Agent dev kit & project structure

CLAUDE.md + Skills + Hooks + Subagents + Plugins. Five layers, each with a different job: CLAUDE.md sets the rules, skills provide expertise, hooks enforce quality, subagents delegate work, and plugins distribute it all to your team. MCP servers and agent teams extend it outward.

The five layers

LayerRoleLoadedLives inThink of it as
1 · CLAUDE.mdMemory: architecture rules, naming conventions, test expectations, repo mapAlways loaded, always active~/.claude/CLAUDE.md (global)
./CLAUDE.md · .claude/CLAUDE.md (project)		The agent's constitution
2 · SkillsKnowledge: reference docs, scripts, templatesOn demand, when the description matches the task.claude/skills/<name>/SKILL.mdModular context chunks. A skill can run in an isolated subagent.
3 · HooksGuardrails: deterministic checks on eventsEvery matching eventsettings.json → hooksGit hooks for your agent. Deterministic, not AI.
4 · SubagentsDelegation: code-reviewer, test-runner, explorer…When delegated.claude/agents/<name>.mdSpecialists with their own context window, model, tools and permissions. They can't spawn subagents.
5 · PluginsDistribution: skills/ agents/ hooks/ commands/Installed oncePlugin marketplace / team installnpm packages for agent capabilities

Show the example settings.json 
{
  "hooks": {
    "SessionStart": [{ "hooks": [{ "type": "command", "command": "./scripts/load-context.sh" }] }],
    "PreToolUse":   [{ "matcher": "Bash",
                       "hooks": [{ "type": "command", "command": "./scripts/block-dangerous.sh" }] }],
    "PostToolUse":  [{ "matcher": "Write|Edit",
                       "hooks": [{ "type": "command", "command": "npx eslint --fix \"$CLAUDE_FILE\"" }] }],
    "Stop":         [{ "hooks": [{ "type": "command", "command": "./scripts/notify-slack.sh" }] }],
    "SubagentStop": [{ "hooks": [{ "type": "command", "command": "./scripts/log-subagent.sh" }] }]
  }
}

A hook command receives the event as JSON on stdin. Exit code 2 blocks the action and sends stderr back to Claude. Script names and the file variable here are illustrative.

Which layer do I need?

I want to…Use
Make the agent always follow our conventionsCLAUDE.md
Teach it how to do X, but only when X comes upSkill
Guarantee something always or never happens, whatever the model decidesHook
Run a big side task without polluting the main contextSubagent
Give the agent GitHub, databases or internal APIsMCP server
Share all of the above with my team in one installPlugin
Run several agents in parallel on one problemAgent teams
