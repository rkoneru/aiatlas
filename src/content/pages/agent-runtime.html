Agents in production: runtimes, identity & events

Demo agents run in a chat window. Production agents are triggered by events, run for minutes or hours in the background, act under a verifiable identity, survive crashes, and sometimes operate software through its screen. Walk an event-driven background agent.

Building blocks

APIs, webhooks & events

How agents get started

Triggers: a webhook (new ticket, failed payment), a queue message, a schedule, a file landing in storage, or a chat message. Make handlers idempotent (the same event delivered twice does the work once), acknowledge fast and work asynchronously, and send results back by callback or webhook.

Long-running & background agents

Work that outlives a request

Use durable execution (workflow engines such as Temporal or cloud step functions, or framework checkpointers): save state after every step so a crash resumes instead of restarting. Keep progress in files or a database, not only in the context window. Add heartbeats, timeouts, budgets and a human-readable progress log.

Agent identity & delegation

Who is this agent acting as?

Give each agent its own identity, not a shared service account. For actions on a user's behalf, use OAuth token exchange or on-behalf-of flows to get short-lived, scoped tokens that carry both the user and the agent. Log both identities on every action. Delegation down a chain of agents should only ever narrow scope.

Computer-use & browser agents

Operating the screen

When there is no API, the agent loops: screenshot (or accessibility tree / DOM) → decide → click or type → observe. Slower and more fragile than APIs, and exposed to prompt injection from any web page. Run in an isolated browser or VM, allowlist domains, and require confirmation for purchases, sends and deletions.

Agent front-ends & generative UI

Streaming & progress

Stream tokens and tool progress so people can see work happening. For long runs, show the plan and the current step, with a clear way to stop.

Generative UI

Instead of only text, the agent returns interface components (a form, a chart, a booking widget) that the app renders. MCP Apps, the first official MCP extension, lets a server ship interactive UI that hosts display in a sandbox.

Agent–UI protocols

Open protocols such as AG-UI (an event stream between an agent back end and a front end) and A2UI (declarative UI an agent can send safely) mean front ends don't have to be rebuilt for each framework.

Approval screens

For risky actions, show the exact action, the data it touches and the identity it runs as, with approve, edit and reject. Log the decision with the trace.
