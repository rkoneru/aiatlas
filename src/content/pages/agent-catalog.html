The 30 agents

DASH: the template for every agent

What to define

  • What the agent does: one job only. If it needs two sentences, it's two agents.
  • What failure it prevents: "without this, [specific bad thing] happens".
  • Who it's for: builder and user often need different success criteria.
  • When it triggers, and where it sits in the stack (foundation → intelligence → integration; don't skip layers).

Prompt must-haves

  • Task: exactly what to do, specific, not generic.
  • Protocol: the step-by-step process the agent follows.
  • Constraints: what it must never do. Negative rules matter.
  • Stop: when to halt. Always define it before deploying.
