3 · MCP

Model Context Protocol & server roles

A standard way for LLM applications to use tools and data. Hosts (an IDE, a desktop assistant, an internal playground) run MCP clients that talk to MCP servers, which wrap real systems like a CRM, a SQL warehouse or a file drive.

Why a standard: M × N → M + N

Custom integrations without MCP (M × N)
With MCP: one client per host, one server per tool (M + N)

The primitives

Servers expose

Tools model-controlled
Functions the model can call, e.g. run_query, create_ticket, described with JSON Schema.

Resources app-controlled
Read-only context addressed by URI, e.g. file:///guide.md, DB rows.

Prompts user-controlled
Reusable templates and workflows the user can invoke.

Clients offer

Sampling
The server asks the host's LLM to generate something, so the server needs no model keys of its own.

Roots
Which folders or URIs the server is allowed to work within.

Elicitation
The server asks the user for missing input mid-task.

Transport: JSON-RPC 2.0 over stdio (local servers) or Streamable HTTP (remote servers, with OAuth for authorization).

The 7 architectural roles of an MCP server

Not all MCP servers are the same. Choosing the right role keeps servers purpose-built, composable, secure by design and production-ready. Pick a role to see its flow.

Purpose-built

Each role solves one problem better.

Composable

Combine roles into powerful agent systems.

Secure by design

Isolation, auth and state management where they matter.

Production-ready

From simple tools to complex enterprise workflows.

Composing roles

Real deployments combine roles. A typical enterprise setup has a Gateway Connector in front of several Tool Lean-in servers, which centralizes auth, rate limits and logging. Context Providers feed RAG-style reads. A Sandboxed Executor is the trust boundary for code. Workflow Packagers expose approved runbooks so the agent can't improvise risky steps.

Governance

MCP is an open standard. Anthropic donated it to the Agentic AI Foundation (AAIF), a Linux Foundation project formed in December 2025 that also hosts A2A, AGENTS.md and goose. The spec ships in dated versions (the latest is 2026-07-28) under a formal deprecation policy with at least twelve months' notice. See what changed in the 2026-07-28 spec.
