ADLC & LLMOps

An AI feature is never "done". Prompts, models, data and user behavior all drift. LLMOps is the loop that keeps quality measurable: golden datasets and benchmarks offline, CI gates on every change, canaries and A/B tests online, monitoring in production, and human feedback flowing back into the eval set. Walk the loop.

Offline evaluation

Golden datasets

Your private benchmark

A versioned set of realistic inputs with expected outputs or grading rubrics. Start with 50–100 cases from real traffic, stratified by intent, difficulty and risk, and add every production failure as a new case. Keep a held-out slice you never tune against. Re-label when policy changes.

Public benchmarks

Useful, but not your use case

Knowledge (MMLU-style), expert reasoning (GPQA), coding (HumanEval, SWE-bench), agents and tool use (τ-bench-style), long context and safety suites. Use them to shortlist models. Beware contamination (test data leaking into training), saturation (everyone scores ~90%) and leaderboard gaming. Your golden set decides.

Shipping changes safely

Prompt & model versioning

Every prompt, model ID, temperature, tool set and retrieval config is a versioned artifact in a registry or the repo. Every response logs which version produced it.

CI eval gates

A pull request that changes a prompt runs the golden set. Block the merge if the score drops or any critical case regresses.

Canary & rollback

Release to a small share of traffic first, compare metrics, and keep one-click rollback to the previous version.

A/B tests & online evaluation

Randomize users between variants and compare business metrics (resolution, conversion, edits) plus sampled LLM-judge scores. Fix the sample size in advance; see the calculator below.

MLOps vs LLMOps

MLOps centers on training pipelines, feature stores and model retraining. LLMOps adds prompt management, retrieval pipelines, judge-based evals, token cost and safety monitoring. Most teams need both.

Data quality & lineage

Track where every document, label and example came from, who can change it, and which model versions used it. Bad or stale data is the most common silent cause of quality loss.

Human feedback loops

Capture

Thumbs, corrections, escalations and reviewer edits, linked to the exact trace and version.

Triage

Cluster failures, label root causes (retrieval, prompt, model, tool, policy) and prioritize by volume × severity.

Close the loop

Every fixed failure becomes a golden-set case, so it can never silently come back.

SDLC ends at deployment. ADLC never stops.

From line to loop. Traditional software ships through sequential, human-driven handoffs. Agents are built, evaluated and improved continuously, and deployment is where the learning starts.
