Agent tools & tool calls

The model never runs the tool. It emits a structured tool call (name + arguments), the runtime executes it, and the result goes back into the conversation state as a ToolMessage. The model then reasons over that result and answers.

Things that go wrong, and where to catch them

Bad arguments

The model can hallucinate IDs or send the wrong types. Validate against the JSON Schema before executing, and return a clear error as the ToolMessage so the model can retry.

Wrong tool

Overlapping tool descriptions cause misrouting. Keep names and descriptions crisp and distinct, and expose only the tools the task needs.

Huge results

A 5 MB result floods the context. Truncate, paginate or summarize in the tool, not in the model.

Side effects

Write tools need idempotency keys, approval gates and audit logs. The runtime is the enforcement point, not the prompt.

Parallel calls

One AIMessage can contain several tool calls. Each result must carry its matching tool_call_id.

Loops

The model can keep calling tools. Cap the steps and detect repeated identical calls.

AI agents need tools

A model on its own can only use what it learned in training. Tools let it decide what information is missing and go and get it: search for public facts, query internal data, do exact math, call systems and read web pages. The agent reads the question, picks a tool, inspects the output, repeats if needed, and returns an answer grounded in what the tools returned.
