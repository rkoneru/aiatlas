Agent payments & commerce protocols

When an agent buys something, three questions need answers: did the user really authorize this, how does the agent check out with the merchant, and how does money actually move? Several open protocols now cover these layers, and they tend to stack rather than compete. Walk a purchase end to end.

Design principles

Explicit, scoped authority

The agent never holds raw card numbers. It holds a token or mandate with a cap, a merchant or category scope, and an expiry.

Human present vs not present

"Buy this cart now" (the user confirms the exact cart) differs from "buy concert tickets under $200 when they drop" (the agent acts later within pre-approved rules). The mandates differ accordingly.

Verifiable audit trail

Signed intent → cart → payment records answer the dispute question: did the user authorize this, and did the agent stay within it?

Agent identity

Merchants and networks need to know which agent is acting, on whose behalf, and whether it's legitimate. This ties back to A2A Agent Cards and signed requests.

This is a fast-moving area. Expect names, adoption and the split between layers to keep shifting. Check each protocol's current spec before building.
