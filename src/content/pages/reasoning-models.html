Models · Reasoning

Reasoning models & test-time compute

Reasoning models think before they answer: they work through the problem in reasoning tokens, check and revise their steps, and only then reply. Spending more compute at answer time buys accuracy on hard problems, at a cost in latency and tokens. Walk one request with an effort setting.

Why it works

Scaling

Test-time compute

Accuracy on maths, code and multi-step planning keeps rising as a model is allowed to think for longer. This added a second scaling lever next to bigger models and more training data.

Training

Learned with reinforcement learning

Models learn to reason by being rewarded for correct final answers on problems that can be checked automatically, such as maths with known answers or code with tests. This is reinforcement learning with verifiable rewards (RLVR); GRPO is a common algorithm. See How models are trained.

Controls

Adaptive thinking & effort

Newer models decide how much to think for each request, and APIs expose an effort level (low to high or max) instead of, or as well as, a fixed token budget. Low effort answers fast; high effort spends more on hard problems.

Visibility

Hidden, summarized or shown

Providers differ in whether you see the raw reasoning, a summary or nothing. Don't build features that parse it, and don't treat it as a faithful explanation of why the model answered as it did.

When to turn reasoning up

TaskEffortWhy
Classification, extraction, routingLow or offPattern matching: extra thinking adds latency, not accuracy
Chat, drafting, summarizationLow to mediumQuality depends more on context than on reasoning
Multi-step analysis, maths, data questionsMedium to highChecking intermediate steps pays off
Coding, debugging, agent planningHighLong chains where an early mistake compounds
Hard research problems, offline batch workMaxAccuracy matters more than time or cost

What changes for builders

Prompting

Say what you want and how it will be judged; skip the "think step by step" scaffolding older models needed. Give context and constraints rather than reasoning instructions. Examples still help with format. See Advanced prompting.

Cost & latency

Reasoning tokens are billed as output and can be several times longer than the visible answer. Leave room for them in the max-token limit, stream the response, and measure cost per task, not per call. See LLM cost estimator.

Routing

Send easy requests to a fast model or low effort, and hard ones to high effort. A router or a cheap classifier often cuts cost more than any prompt change.

Evals

Run your eval set at each effort level. Accuracy usually flattens out; the point where it does is your setting. Re-check on every new model.

Agents

In agent loops the model reasons between tool calls. Keep earlier reasoning in the conversation when the API requires it, and let the agent plan before it acts. See AI agents.

Failure modes

Overthinking simple questions, confident wrong answers after long reasoning, and reasoning that ignores what a tool returned. Guardrails and output checks still apply.
