Agentic coding & software agents

Coding agents read a repository, plan a change, edit files, run the tests and open a pull request. They are the most widely used agents in production, because code gives them something rare: a fast, objective check on their own work. Walk one change from ticket to merge.

What makes coding agents work

Context

Instruction files

A file at the repository root (AGENTS.md, or a tool-specific file such as CLAUDE.md) tells every agent how to build, test and lint, the house conventions and what not to touch. AGENTS.md is an open format hosted by the Agentic AI Foundation. Keep it short and keep it true.

Specs

Spec-driven development

For anything bigger than a small fix, write the spec first: goal, constraints, acceptance tests and the files in scope. The agent plans against the spec, a person reviews the plan, then it builds. Specs double as documentation.

Feedback

Tests are the agent's eyes

An agent is only as good as the checks it can run. Fast unit tests, a type checker, a linter and a reproducible build let it find and fix its own mistakes. Repositories with poor tests get confident, wrong changes.

Isolation

Sandboxes, not laptops

Run agents in a container or a throwaway checkout with no production credentials, a network allowlist and a time and token budget. Let them push only to their own branch.

Review

Review is the new bottleneck

Agents write code faster than people can review it. Keep pull requests small, require CI to pass, use an automated reviewer for a first pass, and keep a named person accountable for every merge.

Tools

Tools, skills & MCP

Give agents the tools developers use, through the command line or MCP servers: issue tracker, docs, logs, read-only database access. Package repeated procedures as skills. See Agent dev kit.

Public benchmarks such as SWE-bench (fixing real GitHub issues) and terminal-task suites help compare models, but they saturate quickly and can leak into training data. Build a small internal set from your own merged pull requests. See Agent evaluation.

Risks & controls

Prompt injection through code

Issues, comments, dependencies and web pages can carry instructions aimed at the agent. Treat repository and web content as untrusted, and never give an agent secrets it doesn't need.

Supply chain

Agents add dependencies readily, and sometimes invent package names that attackers then register ("slopsquatting"). Pin versions, check new packages against an allowlist and scan every pull request.

Destructive commands

Block, or require approval for, commands that delete data, force-push, change infrastructure or touch production.

Skills atrophy

If junior developers never write the code, they never learn to review it. Pair agent use with code reading, design reviews and deliberate practice.

Start with one team, one well-tested repository and one task type, for example dependency upgrades. Measure merged pull requests and review time for a month before widening. See ADLC & LLMOps.
