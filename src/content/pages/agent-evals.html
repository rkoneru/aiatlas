Agent evaluation: trajectories, simulated users & pass^k

Evaluating an agent means judging a whole run, not one answer: did it reach the goal, take sensible steps, use tools correctly, stay within policy and budget, and recover from errors? And does it do so every time? Walk an agent eval pipeline from scenario to release gate.

What to measure

LayerQuestionHow to grade
OutcomeDid it achieve the goal?Check the end state in the sandbox (the database row, file or ticket status), in code where possible
TrajectoryWere the steps sensible?Compare tool calls with expected ones; flag loops, repeats and wrong arguments; use a judge model for the rest
Tool useWere calls valid and safe?Schema validation, tool error rate, calls to forbidden tools
PolicyDid it follow the rules?Rule checks, plus a judge for tone, disclosure and escalation
EfficiencyHow many steps, seconds and tokens?Budgets per scenario; regressions fail the gate
RobustnessDoes it survive surprises?Inject tool errors, timeouts, ambiguous users and planted instructions
ConsistencyDoes it succeed every time?Run each scenario k times; report pass@k and pass^k

pass@k vs pass^k

pass@k: at least one success

pass@k = 1 − (1 − p)k

The chance that at least one of k tries succeeds. Right when attempts are checked automatically and only the best is used, such as a coding agent whose tries are run against tests.

pass^k: every try succeeds

pass^k = pk

The chance that all k tries succeed. Right for customer-facing agents, where every conversation must work. An agent that succeeds 80% of the time has pass^8 of only about 17%.

Both formulas assume independent tries with success rate p. In practice, estimate them directly from your k runs per scenario.

Building the eval set

Start from real work

Turn production transcripts, support tickets and failed runs into scenarios. Twenty to fifty good scenarios beat a thousand synthetic ones at the start.

Simulated users

A second model plays the customer, with a persona, a goal and facts it reveals only when asked. Check the simulator too: unrealistic users make the results meaningless.

Sandboxed environments

Point tools at test systems with resettable state, so you can grade the end state and rerun safely. See Conversation regression testing.

Grade with code first

Use programmatic checks for anything checkable and a judge model only for judgment calls. Calibrate judges against human labels. See LLM as a judge.

Long-horizon tasks

As agents take on longer work, measure the length of task, in human working time, that they complete reliably. Research groups track this "time horizon", and it has been doubling every several months.

Contamination & saturation

Public benchmarks leak into training data and stop separating models. Use them to shortlist, then decide with your own private set, refreshed regularly.
