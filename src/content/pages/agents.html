AI agents: the loop & its anatomy

An agent wraps an LLM in a loop: plan → act → observe → reflect, with memory and tools, until the goal is met or a stop condition fires. The result is closed-loop execution in real systems.

Human control ↔ autonomous action

Autonomy is a dial, not a switch. Move the slider to see which actions in the flight-booking example run on their own and which wait for a human.

Whatever the level, put a fail-closed risk gate in front of irreversible actions (payments, deletes, external messages) and log every tool call for audit and evals.

Agent building blocks

Planner

Breaks the goal into steps (ReAct, plan-and-execute, tree search). Re-plans when observations contradict the plan.

Memory

Short-term memory is the conversation and scratchpad. Long-term memory holds user preferences and past outcomes, read and written by the agent.

Tools

Typed functions with clear schemas: ticketing, email, data tools. Read tools are cheap; write tools need guardrails.

Stop conditions

Goal satisfied, step or token budget exhausted, repeated failure, or human interrupt. Without them, agents loop.

The anatomy of an AI agent

Every agent is the same four parts. A brain (the LLM) runs a loop: perceive, reason, act, observe. Memory supplies context, short-term in the window and long-term in a store. Tools turn the model's function calls into real actions. Guardrails check every action before it runs. The loop ends with a final answer, or when it hits its iteration or budget limit.

The four parts

🧠 Memory

  • Short-term: the context window holds the instructions, the conversation and recent tool results. It fills up fast.
  • Compaction: when it's nearly full, older turns are summarized so the agent keeps the gist and frees room.
  • Long-term: a vector store, knowledge base or files. The agent retrieves the top-k relevant items and writes back what it learns.

🔧 Tools

  • The model emits a function call: a name and JSON arguments.
  • The runtime dispatches it to the right tool (search, code, files, APIs, MCP servers) and executes it.
  • The result comes back as an observation in the next turn's context.

🔁 The loop

  • Perceive the task and context, reason and plan, act by calling a tool, observe the result, reflect, repeat.
  • Stop when there's a final answer (a turn with no tool call), at max iterations, or when the token, time or cost budget runs out.

🛡 Guardrails

  • Validate: is the call well-formed and its arguments safe?
  • Scope: is this tool and this target allowed for this user and task?
  • Budget: are there iterations, tokens, money and rate left?
  • Any failure rejects the action; the agent sees why and adapts. The gate fails closed.

The SPAR framework

Sense → Plan → Act → Reflect: how an AI agent goes from perceiving its environment to taking an action and improving over time. Follow a research agent through all four stages.

The four stages

StageWhat it isTypical mechanismsResearch agent example
S · SenseHow the agent perceives and understands its environmentDocuments, user interface, web search, vector DB, knowledge graphGo through the company DB and the internet to gather facts
P · PlanThe reasoning stage: decide how best to achieve the goalCoT, ToT, GoT, ReAct, Reflexion, Plan-and-ExecuteUse CoT to break the workflow into simple research tasks
A · ActExecute the strategy with digital tools or platformsComputer use, generate docs, call APIs, generate visuals, update DB, schedule tasksBuild an entire PPT from the research output
R · ReflectEvaluate outcomes and improve logic or strategy over timeLLM feedback, user feedback, revise plan, update tool calls, update logsUpdate the draft based on user feedback

Planning strategies at a glance

CoT · Chain of Thought

Reason step by step in one linear chain. Cheap and good for decomposition.

ToT · Tree of Thought

Branch into alternatives, evaluate them, prune. Good for search-like problems.

GoT · Graph of Thought

Thoughts as a graph that can merge and reuse partial results.

ReAct

Interleave reasoning with tool actions and observations. The default for tool-using agents.

Reflexion

Self-critique after attempts, with the lessons stored in memory for the next try.

P&E · Plan-and-Execute

Write the full plan first, then execute the steps, often with a cheaper executor model.
